# Aerix Launcher 2.3.1

A patch for the two crashes reported against 2.3.0. One of them stopped the launcher from starting at all on some phones, and the other killed the dialog that was supposed to explain a missing Java runtime.

## What's fixed

- **The launcher no longer dies while it starts (Android 11+).** The max-refresh-rate switch decides its own default by asking which modes the screen supports, and that question was asked from the Application context - where Android refuses to name a display and throws instead of answering null. It happened inside application creation, before any window existed, so an affected phone crashed on every start and the report came back each time the app was foregrounded. The display is now read defensively, falls back to the default display through the display manager so a fast panel is still asked for, and the preference loader treats the whole question as optional: if the system will not answer, the switch simply starts off.
- **Runtime errors explain themselves again.** The "runtime missing / install failed" dialog offers *Show more* whether or not a cause was attached to the failure, and tapping it read a message off that absent cause - so the dialog meant to tell you why Java did not install crashed instead. Error text now goes through one path that tolerates a missing Throwable, and the runtime dialog carries its own message into the detail view, so there is always something to read.
- **Backgrounding the game is safer.** The render surface asked its display for a refresh rate at moments when that display can still be null - leaving and returning to the launcher, a resize, a fold. The rate now only changes to a number the display actually reported.

## Important notes

- Install this over 2.3.0; nothing about the app ID or your data changes in a patch release.
- The max-refresh-rate switch behaves as it did: on by default only where a faster mode exists at the current resolution, and the readout still reports the rate the display accepted rather than the one that was asked for.
- The runtime dialog can still tell you the install failed - that is a real failure, usually a device/GPU compatibility problem with the runtime. What it no longer does is crash while telling you.

## Downloads

Choose the full APK for an included Java runtime, or a `-noruntime` APK to download runtimes as needed. Select `arm64-v8a` for 64-bit ARM devices, `armeabi-v7a` for 32-bit ARM devices, or the universal APK for another supported architecture. Checksums are included in `SHA256SUMS`.
