# Aerix Launcher 1.5.6 — the first-run guide stops crashing

A bug-fix release. One crash, reported from a phone on Android 9, is fixed; nothing else changed.

## What was wrong

The first-run tour dims the launcher, cuts a hole around the component it is talking about, and puts
its card beside that hole. To do that it read the highlighted component's position in the window and
then offset the card from it.

On some devices that offset went **negative**. The component the tour was pointing at was not really
on screen — a rail item that sits to the left of the tour's own overlay, a page that was still sliding
in when the tour started, or a card that had already scrolled away. Compose refuses a negative padding
with `IllegalArgumentException: Padding must be non-negative`, and because that happens while the
overlay is being drawn, the launcher closed itself the moment the tour appeared.

```
java.lang.IllegalArgumentException: Padding must be non-negative
    at ...aerix.guide.AerixGuideKt.AerixGuideOverlay$lambda$35(AerixGuide.kt:235)
```

That is the whole report. First launch, Android 9, no way past it — the tour is the first thing that
runs, so the app never got as far as the launcher.

## What changed

- **The highlighted component is clipped to the overlay.** Anything that is off-canvas, still moving,
  or measured to nothing is ignored for that step.
- **A step whose component is not visible falls back to the centred card.** The tour keeps going
  instead of pointing at nothing — tap through it and it finishes as usual.
- **Every padding is clamped.** Finite, never negative, and never larger than the space it is applied
  to, so an odd measurement from any future component cannot take the launcher down either.
- The spotlight hole is only drawn for a component that is actually on screen, and it can no longer
  be drawn outside the overlay.

## What did not change

Everything from 1.5.5 is still here — the eleven animated control themes, the in-game account switch,
the renderer fallback that replaces a broken renderer with Emesis, then GL4ES, instead of killing the
launch, the six HD clips, and the 25 wallpapers.

## Which file to download

| file | for |
| --- | --- |
| `Aerix-Launcher-1.5.6-arm64-v8a.apk` | every 64-bit phone — the one almost everyone gets |
| `Aerix-Launcher-1.5.6-armeabi-v7a.apk` | 32-bit phones, including Android 9 and older |
| `Aerix-Launcher-1.5.6.apk` | universal, for x86 devices and as a fallback |

Each of those also has a `-noruntime` edition: the same launcher with the Java runtime fetched on
demand, so the download itself is much smaller.

The in-app update popup picks the right file for your device automatically and shows which it chose
and how big it is. All builds are signed with the same key.

## Installing

Install over your existing Aerix app; **do not uninstall or clear data**. Instances, accounts, skins,
controls and wallpapers stay exactly where they are.

If a tour you already finished does not replay after updating, that is expected — it only runs on
first launch, or when you tap **Show the guide again** in Settings.
