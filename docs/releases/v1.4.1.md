# Aerix Launcher 1.4.1 — Emesis, built in

## Emesis renderer, no plugin needed

- **The Emesis renderer now ships inside the launcher.** Settings → Renderer → Renderer Backend
  lists **Emesis Renderer** next to Auto and Proton; there is no plugin APK to install and nothing
  to sideload.
- **Every version in one renderer.** `libemesis_renderer.so` brings its own EGL and its own desktop
  OpenGL, and picks the core for the game it is running — the gl4es core for old versions, the Mesa
  core for modern ones — so one entry covers the whole version range.
- **Same behaviour as the plugin it replaces.** The bundled entry hands the renderer the exact
  configuration the Emesis plugin APK declares (`POJAV_RENDERER=opengles3`, the `LIBGL_*` wrapper
  variables, and the renderer library itself as the OpenGL library LWJGL binds), so the two paths
  render identically. **The plugin still works**: if you have `Emesis Renderer` installed as a
  plugin it is still discovered and listed as its own entry.
- The real Emesis artwork is used in the Renderer Backend grid.
- The entry is only listed when its libraries are actually present for the device's ABI, so a
  launch can never land on a renderer that is not there.

## Packaged efficiently

- Emesis is packaged for all four ABIs in the released APKs (`arm64-v8a`, `armeabi-v7a`, `x86`,
  `x86_64`).
- The **testing (debug) build** now packages the two ARM ABIs only, which is what the phones it is
  tested on use; that keeps it inside the size a repository file may have.

## Installing

Install over your existing Aerix app; **do not uninstall or clear data**. This build is signed with
the same key as 1.4.0, so it updates in place.

Two APKs are attached:

- `Aerix-Launcher-1.4.1.apk` — full build with the Java runtimes embedded.
- `Aerix-Launcher-1.4.1-noruntime.apk` — smaller build without an embedded runtime; it downloads the
  runtime it needs and updates the no-runtime edition in place.

Checksums for every attachment are in `SHA256SUMS`.
