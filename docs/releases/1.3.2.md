# Aerix Launcher 1.3.2 — Content management update

## Keep your place
- Refreshing after disabling or deleting content no longer replaces the populated list with a loading screen.
- Retain scroll position per instance and content category.
- Disabling a mod keeps its normal row identity and alphabetical position rather than moving it into a separate disabled group.
- Deletion retains the nearest remaining list position; when necessary, the position is clamped to the remaining items rather than reset to the top.

## Multi-select across content categories
Use **Select items**, then tap rows or checkboxes in **Mods, Resource packs, Shader packs, Worlds/saves, and Screenshots**.
- **Select visible**, **Clear**, and **Done** controls.
- Bulk **Delete** with item-count/name confirmation and an explicit world-data warning.
- Bulk **Enable/Disable** for mods. Worlds and packs are not misleadingly "disabled" by renaming their folders.
- Hidden selections are counted when filtering. Select visible adds only the visible results.
- Successful operations are deselected; failures are reported and kept selected for retry.
- Operations use a snapshot of the selected files and do not overwrite conflicting enabled/disabled copies.

Single-item deletion also asks for confirmation. All 1.3 features and the 1.3.1 keyboard changes remain included.

## Downloads
- **Aerix-Launcher-1.3.2.apk** — recommended full APK, including the Java runtime.
- **Aerix-Launcher-1.3.2-noruntime.apk** — smaller alternative without the bundled runtime.

Install over your current Aerix Launcher. **Do not uninstall or clear app data.** Back up important worlds and settings before upgrading. Confirmed deletion permanently removes the selected files/world data.

## Validation and limits
13 content-management regression tests cover row identity/order, duplicate keys, selection, exact batch targets, partial failures, cancellation, unsupported toggle actions, real-file renaming, overwrite conflicts, and preserving unselected worlds. Android CI also runs the existing regression suite, builds both APK editions, and runs native FPS checks.

Exact pixel-level viewport behavior, large content collections and font scaling still require device testing. Existing device-specific keyboard, gameplay performance and internal-audio recording limitations remain; automated tests do not establish that every phone issue is resolved.
