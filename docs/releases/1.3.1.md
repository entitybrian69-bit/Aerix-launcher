# Aerix Launcher 1.3.1 — Keyboard hotfix

This release addresses keyboard-opening state handling introduced in 1.3.

## Changes
- Remove the custom timed IME show/retry loop and explicit input-connection restarts.
- Post one explicit keyboard-opening request after the editor is visible, attached and window-focused.
- Allow another keyboard-button tap to retry a rejected opening instead of closing an invisible editor.
- Stop stale keyboard visibility from blocking an explicit open request.
- Avoid mistaking a closing dialog's keyboard for the game's keyboard.
- Keep repeated native open notifications idempotent, without repeated IME work during focus bounces.
- Retain the existing Space, composing-text and chat preservation fixes.

## Downloads
- **Aerix-Launcher-1.3.1.apk** — recommended full APK, including the Java runtime.
- **Aerix-Launcher-1.3.1-noruntime.apk** — smaller alternative without the bundled runtime.

Install over your existing Aerix Launcher. **Do not uninstall or clear app data.** Back up important worlds and settings before upgrading.

## Validation and limits
Automated regression tests cover rejected keyboard opens, recovery taps, stale visibility, dialog/window-focus transitions, cancellation and repeated native requests. Android CI also builds both APK editions and runs native FPS checks.

**Physical-device confirmation is still needed.** These checks do not prove keyboard opening, typing or gameplay lag is resolved for every phone or IME. This release removes repeated keyboard requests; it does not claim a general FPS improvement or a fix for every source of lag.

If the problem remains, report your phone model, Android version, keyboard app, and whether it affects only Minecraft or also launcher text fields.

All other 1.3 features, including recording with selectable audio and the Team Aerix releases tab, remain available. Existing Android/audio-backend recording limitations still apply.
