# Aerix Launcher 2.4.3

This is 2.4.2 again, published properly, plus the one thing it was missing: the launcher now says out
loud when it is a testing build that will never update itself.

## Why 2.4.2 seemed not to install anything

The 2.4.2 release disappeared from the Releases list after it was published. The tag survived, but
the release did not, so GitHub's "latest release" - which is what the launcher's updater asks for -
still answered **2.4.1**. The updater was not broken: there was genuinely nothing newer to offer it,
so it correctly said you were up to date.

2.4.3 is that release, cut again, with the assets in place.

## If you are on the Nightly (or any testing build)

**A testing build cannot install a release over itself, and no signature will fix that.** The
Nightly and debug APKs ship as `net.al.aerixlauncher.debug`; every published release is
`net.al.aerixlauncher`. To Android those are two different apps, so installing the release APK while
the testing build is on the phone creates a second app rather than updating the first - or fails
outright, depending on the device.

The updater used to report that as "no update available", which reads as broken. It now says what is
actually true and points at the releases page. If you are testing with Nightly, install the release
APK from
[releases/latest](https://github.com/entitybrian69-bit/Aerix-launcher/releases/latest) to be on the
release channel.

## Updating over what you already have - read this if you are on 2.4.1

**2.4.3 will not install over 2.4.1, and no future release will either.** That is not a bug in this
build and it cannot be fixed in this build. It is worth explaining, because the reason is subtle and
we got it wrong more than once.

The published 2.4.1 is signed with **two** certificates: the current key plus the retired key, which
it carried so that installs from 2.3.2 and older could move across without an uninstall. Android
treats a multi-signed install as unable to rotate: `SigningDetails.checkCapability` requires an
**identical** certificate set from the update, saying "multiple-signer packages cannot rotate signing
certs". Every release since carries the current key alone, so the sets never match again. Android
refuses with `INSTALL_FAILED_UPDATE_INCOMPATIBLE`.

Sharing a certificate is not enough, which is the part that misled us: the overlap rule applies to a
*single-signed* install, where rotation history can prove the old key. 2.4.1 has two signers, so that
path never runs.

**What to do, once - and an uninstall really does delete data, so read this first:**

On Android 10 and newer the game files live in Aerix's *app-specific* external storage, not in a
folder you can see from a file manager:

- `/sdcard/Android/data/net.al.aerixlauncher/files` - instances, worlds, `/sdcard` mapping
  (on Android 9 and older it is `/sdcard/games/PojavLauncher` instead)
- app-private storage, which no file manager can reach - `/accounts` (your logins) and `/runtimes`
  (downloaded Java runtimes)

**Uninstalling deletes all of it.** Do not just uninstall and hope.

1. Open an instance, choose **Export**, and tick **Worlds (saves/)** along with the mods and configs.
   Pick any format - Modrinth, CurseForge and MultiMC all keep the files themselves under
   `overrides/` or `.minecraft/`, so the archive is a real copy, not a shopping list. Send it through
   the share sheet to somewhere outside the app, such as Drive, or move it off the device.
2. Repeat for every instance you care about.
3. Note your account details. Exported instances carry your worlds, mods and configs, but **not your
   logins**, and the new install downloads Java runtimes again.
4. Uninstall Aerix Launcher, then install 2.4.3 from the downloads below.
5. Unpack each archive into that instance's game folder, keeping the contents of `overrides/`.

That is the only way off 2.4.1 without the retired key. After it, every future release installs in
place normally, because 2.4.3 is single-signed and so is everything built after it.

- **On 2.4.2:** install straight over it. 2.4.2 is single-signed, so no uninstall is needed.
- **On 2.3.2 or older:** you cannot install this directly either. Install **2.4.1** first - it carries
  both keys, so it does install over 2.3.2 - and then follow the three steps above.

## Still in this build, from 2.4.2

- **The FPS overlay switch moves when you flip it**, and sits directly under **Resume** instead of
  below the fold. The pause menu, the A menu tile and the information page all call it the same
  thing now: FPS overlay.
- **Tap a key** in the pause menu sends any key into the game as a real held press, for a client whose
  menu is bound to a key your touch layout has no button for.
- **Hide the logo while you play**, from the card you get by holding it or from Controls in the
  launcher. It returns whenever the in-game menu is open, so the menu always has a way back.
- **A physical mouse works**: its left click no longer arrives as the right button, and the launcher
  stops drawing its own arrow over the real pointer.
- **Updates that install themselves:** the updater accepts `-noruntime` archives again (it compared
  their version string against the bare tag and refused every one), and it accepts any signer match
  rather than demanding identical signer sets, which is Android's own rule.
- **A launch that dies leaves a reason** in the Log screen under **Launch status (failed)**.

## Downloads

Choose the full APK for an included Java runtime, or a `-noruntime` APK to download runtimes as needed.
Select `arm64-v8a` for 64-bit ARM devices, `armeabi-v7a` for 32-bit ARM devices, or the universal APK
for another supported architecture. Checksums are in `SHA256SUMS`.
