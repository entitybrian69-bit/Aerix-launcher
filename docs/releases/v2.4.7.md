# Aerix Launcher 2.4.7

**This release installs over 2.4.6, 2.4.5, 2.4.1, and older release builds in place**, fixing
native launch/exit crashes on 32-bit and modern Android devices, eliminating the `libandroid.so`
GLFW surface-lifecycle `SIGSEGV`, deferring `:game` WebView initialization, and keeping Discord
Rich Presence visible for 5 minutes after leaving the launcher.

## What changed

- **Native launch & exit crash fixes:**
  - Fixed `abort_wait` treating `EINTR` from `futex` as a child exit and prematurely invoking
    `System.exit(0)`.
  - Fixed `jre_launcher.c` `prepareSignalHandlers()` wiping `sigaction` flags for JVM-critical
    signals and guarded `native_library_hook.c` fallthrough/null-pointer edge cases.
  - Added crash breadcrumbs and `latestlog.txt` `fdatasync` flushing in `stdio_is.c` and
    `GameRunner` so failures during early startup always record their cause.
- **32-bit `SM-M015G` / GLFW surface-lifecycle `libandroid.so` `SIGSEGV` & WebView fixes:**
  - Added native `ANativeWindow_*` null guards, `Surface.isValid()` probes, and serialized
    surface-lifecycle synchronization around `android_window.c` / `_glfwManageEglSurfaceAndroid`,
    plus a timed predicate guard on `nw_egl_cond` to eliminate the upstream lost-wakeup deadlock.
  - Serialized Java surface lifecycle callbacks across `Platform`, `GLFWBackend`,
    `SurfaceViewSurfaceProvider`, `TextureViewSurfaceProvider`, `GameView`, and `GameActivity`.
  - Deferred `WebView.setDataDirectorySuffix` in `:game` / `:recorder` until the in-game skin
    preview actually opens a `WebView`, avoiding eager `android_webview` native memory pressure on
    32-bit devices.
- **Longer-lasting Discord Rich Presence:**
  - Leaving the launcher now keeps `"In the launcher"` (and your current launcher activity) alive
    on Discord for a **5-minute** grace period instead of clearing immediately on app switch, while
    still clearing cleanly on timeout, explicit game exit, or swiping Aerix from Recents.
  - Backgrounding a running game (`!isFinishing`) likewise preserves the in-game card for 5
    minutes, and `ServiceConnection` recovery clears stale Binders cleanly.
- **Double-signed permanently (carried forward from 2.4.4–2.4.6):** Carries both the current
  signing certificate and the retired certificate so existing release installs (`2.4.6`, `2.4.5`,
  `2.4.4`, `2.4.3`, `2.4.2`, `2.4.1`, and `2.3.2` or older) update straight over in place without
  uninstalling or losing worlds, instances, accounts, or runtimes.

## What to expect

- **On 2.4.6, 2.4.5, 2.4.4, 2.4.3, 2.4.2, or 2.4.1:** installs over it in place and keeps all
  instances, worlds, mods, accounts, and downloaded runtimes.
- **On 2.3.2 or older:** installs over it directly too, because it still carries the retired key.
- **On Nightly/Debug (`net.al.aerixlauncher.debug`):** Android treats testing builds as a separate
  package (`applicationId`), so release builds install alongside rather than over testing builds.

## The signing trade, stated plainly

Every release from 2.4.4 on is signed with both keys, permanently. The retired key is public in
this repository (`tests/aerix_legacy.p12.b64`), which means anyone with repository access can build
an APK that installs over an existing launcher. See
[`docs/signing-policy.md`](https://github.com/entitybrian69-bit/Aerix-launcher/blob/v3_openjdk/docs/signing-policy.md)
for the full AOSP reasoning and rules that still hold.

## Downloads

Choose the full APK for an included Java runtime, or a `-noruntime` APK to download runtimes as needed.
Select `arm64-v8a` for 64-bit ARM devices, `armeabi-v7a` for 32-bit ARM devices, or the universal APK
for another supported architecture. Checksums are in `SHA256SUMS`.
