# Aerix Launcher 2.4.2

This is the release that makes the in-game menu behave the way it looks like it behaves, and fixes
two bugs that stopped updates installing over an existing launcher.

## Updating over what you already have

**If you are on 2.4.1, this installs straight over it.** Your instances, worlds, accounts and settings
are kept. Do not uninstall.

**If you are on 2.3.2 or older**, install **2.4.1** first and then this one. 2.3.2 and everything
before it were signed with a key that had been committed to the public repository, so that key was
retired and every release since refuses to carry it. 2.4.1 was the one build signed with both keys,
which is what moves an older install across without an uninstall. Two taps, nothing lost.

## Fixed: updates that would not install themselves

Two bugs in the launcher's own updater, both of which only showed up when it was asked to install an
update rather than merely download one:

- **The `-noruntime` editions could never update.** The updater compared the archive's version string
  against the release tag, but the noruntime flavor appends `-noruntime` to that string, so every
  attempt ended at "version or runtime edition does not match" while the release page looked correct.
- **A double-signed update was refused.** The updater demanded that the installed and downloaded
  signer sets be *identical*. Android's actual rule is that *any* signer may match, which is exactly
  how 2.4.1 moved installs off the retired key. Our own updater would have rejected that build.

## The in-game menu

The menu opened by the Aerix logo is where a player is mid-game, so it should be the place these
things live.

- **The FPS overlay switch moves when you flip it.** It read the setting through a call Jetpack
  Compose cannot observe, so the counter turned on and off while the switch kept drawing its old
  position - which reads as a switch that does not work. It now draws real state, re-read every time
  the menu opens, and it sits directly under **Resume** instead of last in a scrolling list where a
  phone in landscape never showed it.
- **One name for one setting.** The pause menu said "FPS counter", the A menu tile said "FPS Counter"
  and the information page said "FPS pill on screen" - all three drive the same readout. All three say
  **FPS overlay** now.
- **Tap a key.** A ghost or hack client opens on a key binding, and a touch layout has no button for
  most of them - Right Shift being the usual one. The menu can now send any key into the game as a
  real held press, so a client whose jars load but whose menu never appears is reachable from a phone.
  A single-frame tap is missed by a client that polls once per tick, which is why this holds the key
  down briefly instead.

## The logo, and the mouse

- **Hide the logo while you play.** Hold the logo for its card and turn on **Hide while playing**: it
  disappears while you play and comes back whenever the in-game menu is open, so the menu always has a
  way back to itself. It is still shown in the controls editor, and still hidden when your layout
  carries its own MENU button. The same switch is in the launcher's **Controls** settings, so it can
  always be turned back on without entering the game.
- **A physical mouse works.** Android reports the left button as `1` and the game counts from `0`, so
  every left click was arriving as the *right* button - the launcher's own bug, not the mouse's. Fixed,
  along with the second arrow: a mouse that only reports hover never moved the launcher's cursor, so
  the launcher's arrow sat frozen while the real pointer moved elsewhere. Once a pointer is seen, the
  launcher stops drawing its own.

## Launch failures

"The game kicks me back to the home screen" with no log is not something anybody can act on. The launch
breadcrumb now keeps the last 24 stages plus the reason and stack trace instead of one overwritten
line, the game process's crash handler records the uncaught exception, and the Log screen leads with a
**Launch status (failed)** entry.

This does not fix a kick on its own - it makes the next one answerable. If it happens to you, open the
Log screen and share that first entry.

## Downloads

Choose the full APK for an included Java runtime, or a `-noruntime` APK to download runtimes as needed.
Select `arm64-v8a` for 64-bit ARM devices, `armeabi-v7a` for 32-bit ARM devices, or the universal APK
for another supported architecture. Checksums are in `SHA256SUMS`.
