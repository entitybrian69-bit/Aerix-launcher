# Aerix Launcher 2.3.3

**This is a security release, and we owe you the whole story rather than a changelog.**

Someone installing Aerix has been getting Android's "virus" / "app may be harmful" warning. Two things
were behind that, and only one of them was a scanner being over-cautious.

Every APK we had published, from 2.3.0 through 2.3.2, was signed with a key that was **committed to our
public repository** - and the password to use it was written in the file next to it, so CI did not even
need to be told. We have now retired that key for good.

What that did and did not mean: it did **not** put your worlds, accounts or files at risk, and nothing
was found tampered with. It meant that anyone who cloned the repository could build a fake "Aerix
update" that your phone would trust as ours. That is not an acceptable way to run a launcher, whatever
the odds of it being abused.

## What changed

- The release signing key is gone from the repository and lives only in CI secrets, decoded at build
  time into a temporary directory. The password default is deleted, so a build that forgets the secret
  now produces an unsigned APK that CI refuses to publish, instead of quietly signing with a public key.
- The retired key's certificate fingerprint is permanently banned in CI: every APK's signers are read
  back out of the finished file and any release touching that fingerprint fails. This applies to forks
  too, because the check is in the workflow.
- `*.p12` and `*.pkcs12` are now gitignored, so a key in that shape can never be re-added by a future
  merge from upstream. The four inherited Pojav keystores that remain in the tree are deliberately left
  alone: they are unusable without a password we do not publish, and Android CI legitimately signs the
  Google Play build with one of them.
- Play Protect's other complaint was fair: the launcher requests permissions a scanner does not like,
  most of them because of what a launcher has to do (installing its own updates, finding renderer
  plugins, recording video with mic). We cannot make the list empty, but we can stop looking guilty:
  the app is now signed by a key only we hold, and this page says so plainly.

## Installing this release: read this one paragraph

This release is signed by **both** the retired key and the new one, so it installs over 2.3.2 and over
anything older, with your data intact. **Do not uninstall to update.** The *next* release after this one
will be signed only with the new key, and by then everyone will have moved across.

If you installed 2.3.2 and then uninstalled it, or your device kept refusing the update, install this
APK directly from the Downloads list below - that is a clean install, so re-add your instances first.
You can confirm which key an APK carries with `apksigner verify --print-certs Aerix-Launcher.apk`: from
now on the release signer's fingerprint must **not** be
`fba0764460bf766ac2491c714ded1859201e5bf7ef3e8c276e49261845b279db`, the one that was in the repository.

## Also fixed

The 2.3.2 start-up work is unchanged and still in this build: a crash on open can no longer skip the CPU
read or the bundled Java runtime, the architecture is worked out on demand, an install failure now
carries the reason behind *Show more*, and the crash screen keeps its trace in the launcher's own files
instead of asking for a permission that Android 11+ does not offer.

## Downloads

Choose the full APK for an included Java runtime, or a `-noruntime` APK to download runtimes as needed.
Select `arm64-v8a` for 64-bit ARM devices, `armeabi-v7a` for 32-bit ARM devices, or the universal APK for
another supported architecture. Checksums are included in `SHA256SUMS`.

If your security app still warns you after this release, tell us in Discord - with a screenshot - because
now we can prove what signed it.
