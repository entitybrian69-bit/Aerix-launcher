# Aerix Launcher 1.3.4 — CurseForge client hotfix

- Fix category/version response parsing: CurseForge's `data` wrapper is now handled correctly instead of treating the entire response as an array.
- Share the same validated official/mirror routing between Discover and the modpack installer. Remove reflection-based installer routing.
- Retry the existing metadata mirror after an official request fails or returns an invalid response. Do not forward official API credentials to the mirror.
- Keep valid empty responses and search filters intact; a service failure is not reported as an empty successful result.
- Add finite API connection/read timeouts and an explicit Aerix client identity. Clean up failed connections and avoid dumping entire responses to logs.
- Do not incorrectly classify every no-key connection failure as a missing-key problem.
- Handle blank build-key configuration and missing optional modpack metadata safely.

The chat correction fixes remain included. RustGL stays removed. Social features remain design-only and are not included.

## Downloads
Full APK includes Java runtimes. The no-runtime APK is smaller and can reuse installed runtimes. Install as an update; **do not uninstall or clear app data**.

## Verification limits
Regression tests use deterministic official/mirror response fixtures, failure and cancellation cases, credential isolation, query preservation and HTTP connection policies. Android CI builds both APKs and runs the existing regressions and retired-renderer checks. Live CurseForge/MCIM availability and the original phone failure cannot be verified from this restricted workspace; this hotfix corrects confirmed client defects, not remote service outages. API access still depends on a valid configured key or the availability of the existing public metadata mirror.
