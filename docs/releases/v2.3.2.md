# Aerix Launcher 2.3.2

**We're sorry.** Two of you spent the last two days with a launcher that crashed when you opened it, told you your internet was broken, and then asked you for a storage permission that no longer exists on your Android version. All three of those were the same bug in our code, and the second one — "Failed to install Java 8. Please check your Internet connection" — was us blaming your connection for a mistake we made. Your connection was fine. This is the release where we own that.

## What was actually wrong

In 2.3.0, one optional question — "does this screen have a faster mode?" — was asked while the launcher was still starting up, from a context that Android refuses to answer. The refusal threw, and because the startup code was one block, that single throw skipped the two lines after it: reading your CPU architecture, and unpacking the Java runtime that ships inside the full APK.

That is how a crash on open also became "no runtime is being downloaded". The architecture was left unset, and the runtime file name is built from it, so the launcher went looking for a file called `bin-null.tar.xz` — in the APK and on the download server alike. Nothing on your phone or your network was at fault.

## What's fixed

- **The crash on open is gone** (it was already fixed in 2.3.1 — the display query is guarded now, and falls back to the display the launcher is allowed to ask about).
- **A startup failure can no longer cost you your runtime.** Reading preferences, knowing the CPU and installing the bundled Java are three separate steps now. If any one of them fails, the others still run and the failure is reported at the end instead of jumping over the rest of startup.
- **The architecture is worked out on demand**, not only if some earlier line happened to run. If it was never set, the launcher computes it the first time something needs it — so a `bin-null.tar.xz` can't be asked for at all, and the runtime manager and the download list agree with it.
- **"Check your Internet connection" now comes with a reason.** When the launcher knows why an install failed — no entry for this architecture in the runtime bundle, a download that was cut short, a signature that didn't verify — it attaches that as the cause, and *Show more* shows it. If your connection really is the problem, the report will now prove it.
- **The crash screen keeps the trace without asking for permission.** It writes into the launcher's own files, which needs nothing from you, and says where it put it. If even that fails, it says so and points at COPY rather than blaming a permission you can't grant.

## What to do

Update, then open the launcher once and let it sit on the home screen for a few seconds — that first launch is when the bundled runtime unpacks. Then Java 8 should read **Installed** under Settings → Java. If a full build still shows every runtime as Not Installed after that, *Show more* will now carry the real reason; send us that text and we'll fix it, because that would be a different bug and we want to see it. If you would rather not wait for a bundled runtime at all, the `-noruntime` APKs fetch one when you install it from the runtime manager.

## Downloads

Choose the full APK for an included Java runtime, or a `-noruntime` APK to download runtimes as needed. Select `arm64-v8a` for 64-bit ARM devices, `armeabi-v7a` for 32-bit ARM devices, or the universal APK for another supported architecture. Checksums are included in `SHA256SUMS`.

Everyone else: 2.3.2 is a small patch on top of 2.3.1 and 2.3.0 — install over the top, your worlds, instances and controls stay exactly where they are.
