# Aerix Launcher 2.5.0

**This release installs over 2.4.7, 2.4.6, 2.4.5, 2.4.1, and older release builds in place**,
bringing the revamped Music's & in-game Music player, automatic Android ARM64 Flashback mod
compatibility, a low-end intro splash compatibility fallback, and LTW modded renderer hardening.

## What changed

- **Music's Page & Zero-Lag In-Game Music Player:**
  - Redesigned the launcher **Music's** view and the in-game **Music** deck (`InGameMusicPanel`)
    with Audius search/streaming, sorting, playlists, offline downloads, and local `musics/` folder
    playback, keeping Discord Rich Presence updated with the active track.
  - Fixed Now Playing cover artwork failing to update when switching songs (`MusicArtworkImage`).
  - Removed the overflowing bottom switch in the launcher Music view and replaced the bottom
    pagination bar with a slim left-aligned strip for easier song scrolling.
  - Isolated per-second progress ticks (`ACTION_MUSIC_POSITION_TICK`) and HUD telemetry updates from
    the song list and overlay menu, moved initial storage reads off the main thread, and capped
    RGB565 artwork decoding for smooth in-game overlay performance.
- **Automatic Flashback Fabric Mod Compatibility:**
  - Bundled Android AArch64 Dear ImGui natives (`libimgui-moulberry90-java64.so` and
    `libc++_flashtoch.so`) in `arm64-v8a` and added the `:aerix_flashback_compat` bridge injected
    automatically when Flashback is present in `mods/`.
  - Safely guards desktop file dialogs (`NativeFileDialog` / `SDLDialog`), OpenAL loopback calls,
    unsupported `mediacodec`/`v4l2m2m` probes, zero-sized B3D scissor rects, and missing Bionic
    FFmpeg natives (preserving `PNG_SEQUENCE` export cleanly), while automatically selecting LTW on
    `Follow Global`.
- **Low-End Device Intro Splash Fix:**
  - Switched `AerixIntroSplash` from behind-window `SurfaceView` to a `TextureView` overlay to
    prevent compositor black screens on low-end GPUs and OEM ROMs.
  - Added a 720p30 Constrained Baseline (`aerix_intro_compat.mp4`) fallback with `MediaCodecList` /
    RAM preselection and automatic fallback on decoder errors or stalls.
- **Modded LTW Renderer Hardening (1.20.1+):**
  - Hardened `ltw_compat_guard` around framebuffer depth/stencil attachments, base-vertex draw paths,
    and shader/state queries for modded renderers such as Epic Fight.
- **Double-signed permanently (carried forward from 2.4.4–2.4.7):** Carries both the current
  signing certificate and the retired certificate so existing release installs (`2.4.7`, `2.4.6`,
  `2.4.5`, `2.4.4`, `2.4.3`, `2.4.2`, `2.4.1`, and `2.3.2` or older) update straight over in place
  without uninstalling or losing worlds, instances, accounts, or runtimes.

## What to expect

- **On 2.4.7, 2.4.6, 2.4.5, 2.4.4, 2.4.3, 2.4.2, or 2.4.1:** installs over it in place and keeps all
  instances, worlds, mods, accounts, and downloaded runtimes.
- **On 2.3.2 or older:** installs over it directly too, because it still carries the retired key.
- **On Nightly/Debug (`net.al.aerixlauncher.debug`):** Android treats testing builds as a separate
  package (`applicationId`), so release builds install alongside rather than over testing builds.

## The signing trade, stated plainly

Every release from 2.4.4 on is signed with both keys, permanently. The retired key is public in
this repository (`tests/aerix_legacy.p12.b64`), which means anyone with repository access can build
an APK that installs over an existing launcher. See
[`docs/signing-policy.md`](https://github.com/entitybrian69-bit/Aerix-launcher/blob/v3_openjdk/docs/signing-policy.md)
for the full AOSP reasoning and rules that still hold.

## Downloads

Choose the full APK for an included Java runtime, or a `-noruntime` APK to download runtimes as needed.
Select `arm64-v8a` for 64-bit ARM devices, `armeabi-v7a` for 32-bit ARM devices, or the universal APK
for another supported architecture. Checksums are in `SHA256SUMS`.
