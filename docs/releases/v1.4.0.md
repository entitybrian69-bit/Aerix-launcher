# Aerix Launcher 1.4 — Proton, built in

## Proton renderer, no plugin needed

- **Proton (OpenGL over PowerVR) is now bundled in the launcher.** Install the APK and pick it in
  Settings → Renderer → Renderer Backend; there is no second APK to download and no plugin to
  sideload.
- **32-bit devices only.** The bundled PowerVR driver is `libpowervr.so` for `armeabi-v7a`; Proton
  is listed as `32-bit devices only` and the tile carries a **32-BIT ONLY** badge. On a 64-bit
  install the entry is absent rather than broken.
- The real Proton wordmark is used in the Renderer Backend grid. The leftover placeholder renderer
  tiles are gone: the grid shows **Auto (Smart Pick)** and **Proton** and nothing else. Every
  renderer stays available in Global Renderer and in the per-instance editor.

## Contribution tab

- A new **Contribution** entry sits between Settings and your account in the rail.
- It shows the people behind the launcher: the owner on top, the two co-owners side by side, each
  logo a circle with its card underneath — role, name, what they do.
- Tapping a circle opens that person's page: their logo in the top corner, their duties below.

## Downloads land in the right instance

- The install dialog no longer ticks every instance on the device. It ticks **one**: the instance
  you are playing when the file was built for it, otherwise the first instance the file fits, and
  nothing at all when it fits none — so a 1.16.5 build can never be quietly queued into a 1.12.2
  world.
- Matching checks the file's Minecraft versions and, for mods, its loader (Quilt runs Fabric mods).
  `1.16` covers the whole 1.16.x line.
- Rows now say what the file needs — **`needs 1.16.5`**, **`Fabric only`** — instead of the old
  `not for 1.12.2`, which read as if the file were for 1.12.2. `Detected` only appears when the
  instance actually fits.
- The dependency list is resolved against the same instance the dialog picks, and the header names
  it.
- A project page no longer marks every version group as matching when the launcher knows no
  instance version.

## Versions read correctly

- Instance cards showed the loader's build number instead of the game's version: the home card read
  `Fabric 0.16.10` for an instance that is Minecraft 1.16.5. It now reads **`Fabric 1.16.5`**.
- The active-world panel and the recent-worlds list no longer print the raw version id, and library
  rows show the loader name next to the Minecraft version instead of the loader's number as the
  game's.

## Installing

Install over your existing Aerix app; **do not uninstall or clear data**. This build is signed with
the same key as 1.3.6, so it updates in place.

Two APKs are attached:

- `Aerix-Launcher-1.4.0.apk` — full build with the Java runtimes embedded.
- `Aerix-Launcher-1.4.0-noruntime.apk` — smaller build without an embedded runtime; it downloads the
  runtime it needs and updates the no-runtime edition in place.

Checksums for every attachment are in `SHA256SUMS`.
